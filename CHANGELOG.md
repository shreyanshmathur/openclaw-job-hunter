# Changelog

All notable changes to this project. Versions follow the date of the release; the version number lives in
`scripts/jobhunter/__init__.py` and in the guard plugin's `package.json`.

## Unreleased

- Email codes and sign-in links (consent capability `email_codes`, per site, default No): the agent may use a
  code or link a job site emails to the owner, only for its own open request, only from the site's reviewed
  sender domains (`scripts/jobhunter/data/ats_mail.json`, hash-pinned by a test) after a hard deny list
  (Google, LinkedIn, Microsoft, Apple, Facebook, PayPal, banks), within `otp.window_minutes` (10), used once.
  Only HMAC-SHA256 hashes with a per-install salt, the sender domain and times are stored. Typed by code over
  the browser's loopback CDP port; the model never sees it. Caps and a per-site failure breaker
  (`otp_failures`). Works on both email routes.
- Site accounts (consent capability `ats_accounts`, per site, default No): an account with
  `owner.gmail_address`, only for an approved job; the password is generated by code, stored only in the macOS
  Keychain (service `openclaw-job-hunter.<install_id>.ats`) or `private/ats_accounts.json` (mode 600) on Linux
  and WSL (`accounts.key_store`), and typed by code. One account per tenant, reused. Only a required standard
  terms box is ticked; unusual required boxes stop (`account_terms`); every box is logged. Caps and a failure
  breaker (`account_failures`). New commands `./jobhunter accounts list` and `./jobhunter accounts forget
  <host>`. Workday jobs reach the agent only with `boards.sites.workday.apply` set to `browser` and
  `ats_accounts` granted for `workday`.
- CAPTCHA hand-off on ATS forms: the job pauses (`captcha_wait`), the owner gets a chat alert with a
  screenshot and a 4 character code, solves it in the agent's window and runs `/jh continue <code>` or
  `./jobhunter continue <code>`; a read-only check confirms it is gone and the job goes back to the apply queue.
  Timeout after 2 hours (`captcha_timeout`), daily and open limits, a per-site repeat breaker
  (`captcha_repeat`), `./jobhunter captcha list`. The program never solves a CAPTCHA.
- Owner commands: `./jobhunter browser consent` asks the two capability questions per site;
  `./jobhunter browser forget <site>` takes them back (breaker `ats:<platform>`, `consent_revoked`).
- Sheet: Alerts rows for code steps (`S<n>`) and CAPTCHA tasks (`K<n>`), a settings section "Email codes and
  site accounts", a "Job sites:" line in the digest; status and inbox list open CAPTCHA tasks first.
- Installer and doctor: the agent profile's CDP port is recorded as `browser_cdp` in `private/home.json`;
  `doctor` checks it answers and lists the capability consents and the password store availability.
- Guard 2.2.0: `G_SECRET_FIELD` (no model typing into password, code or PIN fields), forbidden clicks on social
  sign-in buttons and CAPTCHA widgets, new never hosts, new ATS platforms, capability-aware stops, the CAPTCHA
  hand-off payload and `/jh continue`.
- Database migration `0003_otp_accounts`: tables `code_requests`, `code_uses`, `code_steps`, `ats_accounts`, `account_terms`, `captcha_tasks`, and the human task kinds for CAPTCHA tasks.
- New config blocks `otp`, `accounts` and `captcha`; see `docs/CONFIG-REFERENCE.md`.

## 2.0.0 (unreleased)

First public version.

- Easier setup on the Claude subscription route: the README starts with a Quick start (the fewest commands from
  a new Mac to a running agent, what each asks and how long it takes), recommends the Claude subscription with
  the API key as the alternative, explains the words it uses, and has Updating and If something goes wrong
  sections. The installer remembers the model route of the first install (`model_route` in
  `private/home.json`), so `./install.sh` and `./jobhunter update` keep an API key install on its key;
  `--claude-login` switches back. A re-run on the API key route no longer asks for a key that onboarding would
  not use. When the installer stops it names the step and what to do next; the Claude login, OpenClaw and Claude
  Code version messages say the exact command and to run `./install.sh` again; OpenClaw's spinner no longer
  floods the browser profile step. `./jobhunter doctor` checks the Claude login on that route, and
  `./jobhunter update` says what each stage does and what to do when the download or the installer fails.
- Claude subscription route without approvals or identity gaps: every jobhunter agent run is a restricted
  OpenClaw run (an automation with an explicit tool list), so Claude Code's own tools and AskUserQuestion are off
  for the agents and nothing waits for a person. Onboarding, the identity probes and the QC reviewer run as
  automations too; no agent is started with `openclaw agent` any more.
- Every jobhunter agent's exec policy is written explicitly as `mode` (allowlist, which is security allowlist with
  ask off; deny for jobhunter-qc), elevated off, no safe bins, and read back from OpenClaw's effective merge
  (`install verify-exec-policy`). OpenClaw 2026.9.5 and later refuse `mode` next to `security` or `ask`, so the
  patch writes `mode` alone and deletes an older install's `security` and `ask` in the same write. The exec
  approvals hold one argPattern per agent: `python -I`, this repo's `jh.py`, a proof that names that agent, the
  guard's token class, anchored at the end, with `autoAllowSkills` false; the read-back fails while
  `agents["*"]` adds allowlist entries (OpenClaw adds them to every agent) or a jobhunter entry holds more.
- `install.sh` adds each agent and restricts it in the same step (8). If the install stops before the read-back
  passed, the agents it added are removed again, or every jobhunter agent is set to exec deny with every tool
  denied, so no jobhunter agent is left with OpenClaw's fallback policy.
- OpenClaw's Skill Workshop (mode auto, its default) runs every agent weekly to rewrite its skills, outside every
  project control. Before adding agents the installer asks to set `skills.workshop.autonomous.mode` to `propose`
  (`--skill-workshop-propose` for `--yes`) and stops otherwise; install step 13 and `./jobhunter doctor` fail
  while any automation outside the manifest that runs a jobhunter agent is enabled (`install foreign-jobs`).
- `install.sh --openclaw-bin <path>` installs with another `openclaw` build (recorded, one clone is one install),
  and without a terminal step 8 skips `openclaw models auth login`, which needs one.
- Agent identity version 2: the guard adds a signed, single-use `--agent-proof` to every `jh.py` command and a
  single-use environment proof; `jh.py` requires the carriers in `cli_route.carriers` (`--identity-carrier`).
- Every field of every automation is recorded in the install manifest (`cron_specs`) and compared before every
  `cron run`; the installer repairs drift with a full-field `cron edit`, else removes and adds the job.
- `install.sh`: a running dispatcher is paused for the whole install and started again only on success; the
  `claude` version is checked; OpenClaw before 2026.9.7 gets a Gateway restart after plugin changes;
  `--no-daemon`; identity probes and a QC turn in step 14 (skipped when the versions are unchanged, `--smoke`
  forces them); `--cli-tools native --i-accept-reduced-protection` as an explicit reduced-protection mode.
- `./jobhunter doctor` shows the exec policy, the agent mode, the last identity check and, in red, every other
  agent with an unconfined shell; `./jobhunter doctor --probe` runs the identity checks.
- OpenClaw 2026.9.8: install step 10 links the guard plugin with `--force` after a confirmation (asked at a
  terminal, `--yes` confirms; OpenClaw cancels the link of a plugin from outside ClawHub otherwise) and writes the
  guard config before `plugins enable`, which now validates it. `./jobhunter doctor` judges `openclaw doctor --lint
  --json` by finding severity (that version reports ok false for warnings only); the `skill-workshop-tool-policy`
  finding of the jobhunter agents is expected. Install step 3 refuses a Claude Code older than a jobhunter model
  needs, and steps 8 and 13 print every stale exec key they unset and every automation they repaired.
- The QC test turn (`qc smoke`, install step 14) sends the reviewer a real review packet with made-up data, whose
  verdict runs well past the 2000 characters OpenClaw 2026.9.8 keeps in the run record, and checks it with the
  reviewer's own parser (nonce and draft hash). The old counting message was not a review packet, so after the
  switch to the verdict file the reviewer refused it and step 14 failed every time on 2026.9.8. A reply the run
  record cut (`ocrun.run_text`) is now a clear failure, never a text. The reviewer prompt names the keys of each
  verdict object (a schema error names them too); re-run `./jobhunter qc golden` after updating.
- `--cli-tools native` uses the argv identity carrier alone (Claude Code's own Bash never gets the environment
  proof); the installer picks it and refuses the environment carrier with that mode. With the environment carrier
  alone `JH_SESSION_KEY` is required. `CLAUDECODE` marks a call as an unproven agent wherever it runs;
  `./jobhunter`, `install.sh`, `uninstall.sh` and the command automations drop it before they start `jh.py`.
  The unconfined-shell check judges an agent's own exec `mode` before `security`. `./jobhunter doctor` shows an
  informational WARN while the guard's tool pin hook has never run (OpenClaw 2026.9.8 needs
  `hooks.allowConversationAccess`, which the installer never grants).

- Five OpenClaw agents (scout, evaluator, applier, outreach, qc) coupled only through a local SQLite ledger,
  started by a code-owned dispatcher at random times inside active hours.
- The `jobhunter-guard` OpenClaw plugin: exec allowlist with argument checks, file confinement, browser typing
  and clicks only under a live send token, stop-page detection, `/jh` chat commands for the owner.
- Duplicate protection in code: one application per job, one cold touch per person, company cooldowns,
  enforced by unique indexes and triggers.
- Researched, conservative limits for Gmail, LinkedIn and job boards, compiled hard maximums, warm up, pacing,
  breakers that only the owner can reset.
- Two-stage QC for every outbound text: a deterministic linter (no dashes, no filler, facts traceable to the
  profile) and an independent reviewer agent.
- Email from your own Gmail in the agent's browser profile by default (no password needed): the compose fields
  are read back and compared with the approved text before the one allowed click, and the send is confirmed in
  the Sent folder. Sending by code over Gmail SMTP with an app password stays available as an option.
- Your existing Chrome logins, with consent per site: `./jobhunter browser consent` explains what is copied,
  asks about each site (default No), lets you pick the Chrome profile by name, records the answers with your PIN
  in `private/consent.json`, then copies only those sites' cookies into the agent's own profile and checks the
  logins read only. `./jobhunter browser forget <site>|--all` takes a site back. Preflight, the send gate and
  the guard refuse any site without consent.
- An optional email finder with your own free-tier keys (off by default; `./jobhunter enrich connect`), limited to
  people on the hiring team of a targeted job, with budgets that stop before a free tier runs out.
- Truthful resume tailoring with PDF and DOCX output and an answer bank that never invents answers.
- A Google Sheet mirror through a bound Apps Script web app, with readable tabs, colors and a dashboard.
- `install.sh`, `uninstall.sh` and the `./jobhunter` control wrapper; every automation is created disabled.
- LinkedIn writes off by default; enabling them needs the owner PIN and a typed acknowledgement.
